Problem

Our competitor research was trapped inside Figma.

The apps we compete with aren't on Mobbin or AppShots. They're fintech products that require accounts, onboarding, and real bank connections to get to the interesting screens. The only way to study them is to have someone actually use them and screenshot what they see.

We had done that. Freelance researchers logging into Chime, Acorns, SoFi, and thirty other apps, capturing flows, pasting screenshots into Figma boards. Hundreds of screens. Properly gathered. Completely inaccessible.

Execs and PMs who needed competitive references had to ask designers. Designers had to hunt through boards. The boards had no search. A PM asking "how does Chime handle payroll?" got a Slack message and a wait.

The problem wasn't that we lacked research. It was that we had no way to surface it.

Goal

What we needed

One secure, private, searchable product. Three types of queries it had to answer.

Designer

How does Acorns show a payroll screen? What does Chime's disclosure copy look like on that flow?

PM

What pricing structure does Experian show? What does their onboarding look like in week two?

Exec

What is their full credit-building flow? How do they pitch the upgrade?

No public tool could do this. Building on top of AppShots or Mobbin wasn't an option. We had to build something ourselves.

Approach

Two weeks of theorizing

I spent the first two weeks not building. Figuring out if this was even possible, and how.

The research data existed as raw images. The question was: how do you make thousands of screenshots searchable? You can't search pixels. You need metadata. Tags, flow labels, feature categories, and text extracted from the screens.

The answer was Claude. Teach it to look at a screenshot and mark it: what flow is this? What feature? What copy is visible? What bureau or partner is mentioned? Feed every image through that pipeline and you get a tagged, structured dataset out the other side.

Once the data was structured, the infrastructure followed.

Images

AWS S3 stores every competitor screenshot. Private bucket, VPN-gated. Images never leave Bright's infrastructure.

Data

AWS RDS stores all metadata: flow tags, feature labels, copy extracted by Claude, ratings, product offerings, category, bureau mentions.

App

Next.js app with its own frontend and backend logic. Queries RDS, serves S3 images. Runs on EC2 inside a private VPC. Bright VPN required to access.

Search

Query the metadata, get the images. A designer types "payroll screen" and gets every app's payroll screen side by side.

Build

Two weeks of execution

The architecture was clear. We built it. V1 went live in four weeks from the first conversation.

After V1, three more releases. V2 added bug fixes, eight new apps, and an AI Inspiration tab. V3 made Atlas queryable from Claude Code directly, published as an MCP plugin. Two install commands and Claude could search Atlas, read competitor screenshots, and pull pricing and legal copy off the screens rather than guessing.

claude plugin marketplace add BrightMoney-AI/bright-competitor-hub

Process

The crash and what it taught me

Three weeks after launch, the site went down. The Next.js app used API gateway keys to access images on S3. Those keys were stored in the setup guide I had shared with the team so everyone could run it locally. DevOps flagged the keys in the repo. We rotated them. The rotation broke the app because there was no fallback.

I had shipped a convenience without thinking about what happens when the credentials inside it get cycled. Fixed it with engineering and built a proper fallback. The lesson: any credential in a shared file is a dependency. When it changes, everything downstream breaks.

"Credentials in the setup guide" — mine

I put API keys in a tutorial.md and shared it with the team. Convenient. Until DevOps rotated them and the site went down. Environment variables from day one, not a markdown file with keys in it.

"Tagging quality determines search quality"

The search is only as good as how well Claude classified the images. Some early tags were too broad. I'd invest more time in the tagging model upfront before ingesting at scale.

Outcome

What shipped

A private, secure competitor intelligence product used by designers, PMs, and execs at Bright. 30+ competitor apps. Searchable by flow, feature, screen type, copy, and pricing. Queryable from Claude Code via MCP. Updated weekly.

The research that was trapped in Figma boards is now findable in under ten seconds.

Reflection

What I'd do differently

  • Environment variables from day one, not a markdown file with keys. Security layer before convenience layer, always.
  • Invest more in the tagging model upfront. The AI classification is what makes everything searchable. Every hour spent improving it at ingestion saves ten in post-hoc cleanup.
  • The 2-week theorize, 2-week build structure was right for something this undefined. Don't touch the keyboard until you know what you're building.
